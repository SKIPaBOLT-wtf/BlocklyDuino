Serial tools: talk to your board and see its data

Keep data in view: collapse the Settings disclosure above the data. Its open/closed state is remembered in this browser, independently for Monitor and Plotter; inner Plotter sections and diagnostics remember their own state too. Status, errors, pause controls and data remain visible. Monitor display preferences and Plotter profiles/settings persist. Board/upload selection is in the main editor and is separate from the shared serial connection.

Monitor is a text terminal with a send box. Plotter turns the same received stream into instruments and charts. Both can stay open together; the server opens the serial port once and sends a copy of incoming data to each window.

First connection

  1. Open Monitor or Plotter from the editor.
  2. Select your serial port. Use Refresh after plugging in the adapter.
  3. Set the same baud rate as the sketch's serial baud block or Serial.begin(...), then press Connect / apply. The last successful port and baud are remembered.

Opening a tool does not open the port automatically. Connecting/reconnecting can reset boards that use the adapter's DTR signal for reset. The existing Upload action releases the port during upload, then reconnects it if it was previously open. An external Arduino IDE monitor must release the port before these tools can use it.

Connect, disconnect and baud changes affect both windows. Pause, filter, Clear view, Clear history and capture are local to the individual view. Closing either window does not disconnect the shared port; use Disconnect when finished.

Send and receive text

Enter text in Monitor and press Enter or Send. Select LF, CRLF, CR or no line ending. The up/down arrows recall the last 20 commands. A newline is a real byte, so a command such as LED 1 with LF sends six bytes. Text is UTF-8.

Use serial bytes available and serial read byte to receive without waiting. The read block returns 0–255, or -1 when empty. serial write byte sends a byte unchanged; serial send prints its decimal/text representation.

Example 54: bidirectional byte echo uses 115200 baud and echoes each byte. It does not accumulate a String or wait for an entire line.

Automatic plotting: no configuration needed

Send one complete sample per line. Use a decimal point, not a decimal comma. These two examples each contain two fields:

512,300
515,302

adc:512 reference:300
adc:515 reference:302

Commas, tabs and spaces separate numeric fields. Labels before a colon give the series names. A CSV header such as temperature,humidity can name subsequent numeric rows. Ordinary log text remains in Monitor and is not plotted. Finish each row with LF or CRLF; Serial.println() does that.

Example 55: automatic plot sends A0 and a reference value 20 times per second. A potentiometer's wiper goes to A0, its ends to 5 V and GND on this 5 V Pro Mini.

Configured dashboards

Use Configure to define fields, units, value transformations, limits and instruments. Supported views: line chart, XY graph, analog gauge, bar gauge, and a raw/calculated value table. The raw value is preserved; the displayed value is raw × scale + offset. Min/max are display bounds after this transformation, not limits that discard samples.

There are two ways to select a dashboard:

ModeHow it works
Auto / controller headerThe sketch sends @plot {configuration} once before its data. Or it sends @use saved-profile-id to select a profile previously saved in this browser.
Manual profileLoad a saved/imported profile or configure one yourself. Controller @plot/@use lines are ignored; incoming data is interpreted with your selected fields.

A complete configuration is a single line. Subsequent samples may be simple CSV rows in field order, or tagged @data records carrying a stream ID and optional device time. The Plotter protocol guide contains the exact schema, bounds and examples.

Example 56: configured potentiometer dashboard sends a header from Flash with F(), followed by two copies of the ADC reading. The PC converts the second copy to voltage and draws five views. The microcontroller needs no JSON parser and no chart buffer. Download its profile.

Keep profiles and measured data

  • Save profile stores a dashboard in this browser. Export profile saves a portable JSON file; Import opens one. Save after importing if you want @use id to find it later.
  • History controls the rolling points shown by charts. Old chart points are discarded; this is separate from capture.
  • Enter a sample count, then Start capture. The next accepted samples are retained until that count, Stop, a configuration change, or the 20 MiB capture limit. Pause view does not stop capture.
  • Save CSV includes receive time, optional device time, stream ID and both calculated/raw fields. Save JSONL also includes the profile. Captures stay in memory until exported; export before closing the tab.
  • Monitor's Save log exports the retained text (up to 200,000 characters / 5,000 records). Its filter does not remove data from the saved log.

Throughput and gaps

The microcontroller sends text sequentially. At 115200 baud with 8N1, the wire carries about 11,520 bytes/s; the number of samples per second depends on row length. Use short CSV rows for small AVR boards. Display refresh is throttled separately, so it need not redraw after every sample.

The server retains up to 4 MiB / 8,192 events for readers. A view that falls behind reports the gap; the missing data cannot be reconstructed. Capturing before the desired measurements start gives predictable results. The port uses 8 data bits, no parity, one stop bit, without flow control.
