Serial Plotter: your own instrument panel

Keep data in view: collapse the Settings disclosure above the data. Its open/closed state is remembered in this browser, independently for Monitor and Plotter; inner Plotter sections and diagnostics remember their own state too. Status, errors, pause controls and data remain visible. Monitor display preferences and Plotter profiles/settings persist. Board/upload selection is in the main editor and is separate from the shared serial connection.

The local Plotter displays live serial data as line charts, XY graphs, analog gauges, bars and raw/transformed values. One sample may feed several instruments. The dashboard runs on the laptop; the microcontroller only sends text.

Start without a configuration

Choose the same baud rate as Serial.begin(...), then Connect. Baud and port are remembered by the local serial service. Opening a view does not automatically connect hardware. Try demo is an explicit simulation and needs no board.

In Auto / controller header mode, any of these newline-terminated formats starts a line chart:

23.5
23.5,47,1023
temperature:23.5 humidity:47
Temperature,Humidity
23.5,47
24.0,46

The last three lines show a CSV column header followed by samples. A tab can replace a comma. Numeric rows without a header get names value1, value2 and so on. Labelled values use the label as their field ID; use simple letters, digits, underscore and hyphen, starting with a letter. Use a decimal point, not a decimal comma. Exponents such as 1.2e3 are accepted. Each sample must contain the same fields; incomplete or malformed samples are reported in diagnostics.

Debug text is left for Serial Monitor and ignored by the Plotter. Once an automatic dashboard exists, a different field layout needs a new explicit header, a loaded profile or a fresh Plotter page. CSV labels are only inferred before a profile exists.

Configure and save a dashboard

  1. Click Configure. Enter a stable profile ID, a title and history size.
  2. Add fields in the order your program sends them. Choose number, string or boolean. Number fields support displayed = raw × scale + offset, a unit, and optional min/max.
  3. Add instruments: Line chart, XY graph, Analog gauge, Bar gauge or Raw / values. For a line/raw instrument enter comma-separated field IDs. XY needs exactly x,y. Gauge/bar needs one numeric field with min and max.
  4. A line or XY instrument may have its own history count; leave it blank to use the dashboard history. Apply the dashboard.
  5. Click Save profile. It is saved in this browser under its profile ID. Use another ID for a different variant. Export profile downloads a portable JSON file; Import loads one, then Save remembers it.

Loading or manually applying a profile selects Manual profile mode. Incoming @plot and @use lines are ignored in this mode. The last saved/selected manual profile reopens next time. Select Auto when you want the controller to choose the dashboard. The saved profile list belongs to this browser and this localhost origin; use exported files to move it to another browser/computer.

Header / MCU code generates the complete one-line header and ready-to-copy Arduino code from the current dashboard. You do not need to retype JSON or flatten an exported file by hand.

Controller-selected dashboard: local protocol v1

This is the BlocklyDuino local dashboard protocol implemented here. It is a text protocol over Serial, not a binary standard. Every message ends with a newline (LF, CRLF and CR are accepted). Send the header before data.

Option A: describe the dashboard

A line beginning with @plot contains a JSON object. This compact example shows an ADC value as volts:

@plot {"version":1,"id":"pot","title":"Potentiometer","history":500,"fields":[{"id":"adc","min":0,"max":1023},{"id":"volts","unit":"V","min":0,"max":5,"scale":0.004887585532746823}],"widgets":[{"type":"line","fields":["adc"]},{"type":"gauge","field":"volts"},{"type":"bar","field":"adc"},{"type":"xy","x":"adc","y":"volts"},{"type":"raw","fields":["adc","volts"]}]}
512,512
650,650
700,700

Both values in each row are the same raw ADC reading. The laptop converts the volts field to volts using scale, so the AVR does not need to format a floating-point voltage. Both original and transformed values are retained in captures. Min/max are display bounds after transformation; they do not clip stored data. A gauge needle/bar stays within its range and marks out-of-range values.

Option B: select a saved dashboard

@use pot
512,512
650,650

The profile ID must already exist in this browser's saved dashboard list. An unknown ID produces a visible message and leaves the current dashboard unchanged. This short header saves Flash and serial bandwidth on a small AVR.

Data with an explicit stream ID and time

@data {"id":"pot","t":1250,"values":{"adc":512,"volts":512}}
@data {"id":"pot","t":1350,"values":[650,650]}
@data [700,700]

Object values use field IDs and may arrive in any order. Arrays and plain CSV rows follow the configured field order exactly. All fields are required in each sample. A tagged data message with another id is ignored so streams cannot silently mix. Untagged arrays/CSV belong to the currently selected dashboard.

t is optional numeric controller time. Choose X axis → Device time (t) to use it unchanged; choose your own unit, for example milliseconds. A sample without t has no point on that time axis. Received time uses seconds since the oldest visible history sample; Sample index is useful for evenly sampled data. An XY graph always uses its configured x and y fields.

Arduino sketch

After saving the pot profile above, this sketch sends compact data. The one-line selection uses Flash storage through F().

void setup() {
  Serial.begin(9600);
  Serial.println(F("@use pot"));
}
void loop() {
  int adc = analogRead(A0);
  Serial.print(adc);
  Serial.print(',');
  Serial.println(adc);
  delay(50);
}

Use Header / MCU code for a sketch with the complete @plot header instead. No JSON library is needed on the microcontroller. Use regular Serial.print calls for variable values; the generated sketch contains placeholder sample values.

The Plotter replays the available shared serial history when opened, so a recent header can be recovered. That history is bounded: if the header has already expired, resend it, load the matching profile, or reset the board to run setup again. A useful sketch can also resend its header when it receives ? from Serial Monitor. Repeating an identical valid header does not clear current chart history.

Configuration fields

KeyMeaning
versionRequired, exactly 1.
idRequired stable ID, 1–48 characters; starts with a letter; letters, digits, _ and -. Also identifies data and saved profiles.
titleDashboard title; defaults to ID.
historyRetained samples, default 500, range 10–10000.
fieldsRequired ordered array of 1–32 field definitions. Each has a unique id.
Field label, unitHuman-readable name and unit; ID remains stable.
Field typenumber (default), string or boolean. Numeric charts accept only number fields. Raw widgets display every type.
Field scale, offsetFinite numbers; defaults 1 and 0. Only numeric fields can be transformed.
Field min, maxOptional numeric bounds with min < max; both required for gauge/bar. Line/XY chart axes otherwise scale to received data.
widgets1–16 instruments. Omit for one line chart of all numeric fields, or raw display if none are numeric.
Widget typeline uses fields:["a","b"]; xy uses x:"a",y:"b"; gauge/bar use field:"a"; raw uses fields.
Widget title, historyOptional title; optional line/XY history from 10 through the dashboard history size.

Boolean input accepts JSON true/false, 1/0, or those strings in a CSV field. Strings are limited to 2048 characters; CSV text containing a comma must be quoted, with quotes doubled. For complex strings use JSON @data and proper JSON escaping. NaN, Infinity, missing fields, extra fields, duplicate field IDs and unknown widget types are rejected rather than guessed.

Capture and save samples

  1. Set Samples to the number of incoming matching samples to retain (1–100000).
  2. Start capture. This records new samples from that point; existing chart history is not included.
  3. Capture stops at the chosen count, at 20 MiB of estimated in-memory data, or when you press Stop. Applying a different dashboard also stops it to preserve the schema.
  4. Save CSV for a spreadsheet, or JSONL for full configuration and typed data.

CSV columns include received ISO time, device time, stream ID, and two columns per field: transformed value and original raw value. CSV string cells beginning with spreadsheet formula markers are prefixed with an apostrophe. JSONL starts with a configuration record; each following line contains one sample with timestamps, values and raw.

Pause view only pauses drawing. Serial reception, bounded chart history, capture and the separate Monitor continue. Clear history does not delete a completed capture. Starting a new capture asks before replacing captured data. Captures live in this page's memory until downloaded; they do not survive closing or refreshing the page.

Practical limits

  • One backend owns the physical serial port; Monitor and Plotter receive the same stream independently. Disconnect, baud changes and upload handover apply to that shared connection.
  • Only one dashboard/stream is active in a Plotter window. Open a separate window for a different manual profile, or let @plot/@use change the current view.
  • Display redraw is limited to about 10 times per second. Large line histories are visually decimated to fit canvas width; peaks between displayed points can be missed. Captures retain all accepted samples up to their limits.
  • Serial events and chart/capture memory are bounded. If the browser falls behind and events are lost, diagnostics reports a gap and discards the partial line. This is a learning/debugging tool, not a lossless high-rate acquisition system.
  • Each serial line is limited to 32768 characters. Use compact configurations on small AVRs; do not allocate a whole large JSON header in RAM. The number of fields is the fields array length, and sample history is laptop memory, not MCU memory.
  • At 9600 baud, a serial byte normally takes roughly one millisecond. Many long JSON samples can fill the transmit buffer and slow loop execution. A short header followed by CSV rows is efficient.
