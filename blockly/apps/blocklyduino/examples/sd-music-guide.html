Play a known melody file

Define one SD card and one passive buzzer in Devices. The example uses SD CS D10 and buzzer D4. Copy MELODY.TXT to the root of a FAT16/FAT32 card, then open the SD melody example.

In setup, play score opens that known file. In loop, service score keeps playback moving. It reads at most 32 input characters on each call and holds only one small note token and the current duration. The complete melody is never loaded into RAM.

File format

# Note and duration in milliseconds
C4 250
D#4 250
R 100
Bb3 500

Notes use A–G, an optional # or b, and an octave digit. C4 is middle C. R is a rest. Duration is 1–60000 ms. Use pitches within 20–4000 Hz; unsupported pitches are errors rather than silently changed notes. A # at the beginning of a record starts a comment. Spaces, tabs, commas and line endings separate fields.

score playing stays true through the final note/rest. score OK becomes false for a missing file, malformed record or read failure. stop score stops the buzzer and closes the file.

Cooperation with other blocks

The score player shares the existing card and its 512-byte cache. It owns the one open file until completion: do not open another file, draw BMPs or append logs on that card while the score is active. It does not prebuffer notes. An SD delay may postpone the next note, while the current note expires through the sound timer.

The melody file example is one voice. For three simultaneous voices, use the Flash-stored score example from the music guide. The same Timer2 restrictions apply. Reading SD is cooperative, not a hard real-time guarantee.

Compiled for Pro Mini ATmega168:12,256 bytes Flash (85%),758 bytes static RAM,266 bytes left for stack and temporary data. The parser passed host tests for malformed files, duration/pitch limits, bounded reads and cleanup. Actual card/buzzer operation has not been tested.
